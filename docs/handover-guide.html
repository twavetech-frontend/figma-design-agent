Figma Design Agent
이관 설명서

터미널에서 AI(Claude)에게 한국어로 지시하면, imin 기획 문서와 Imin Design System을 반영한 화면이 Figma 파일에 자동으로 생성되는 도구입니다. 이 문서 하나로 인수인계가 끝나도록 썼습니다.

최종 갱신 2026-08-18 · 저장소: figma-design-agent

1이 도구는 무엇인가

앱이 아닙니다. 터미널에서 실행하는 Claude Code CLI(AI 비서)가 중심이고, 나머지는 AI와 Figma를 이어주는 배관입니다.

2처음 시작하기

새 컴퓨터 기준 전체 온보딩입니다. 수동으로 할 일은 사실상 두 가지 — 준비 지시 한마디, 플러그인 실행 한 번.

  1. 설치 전제 확인
    Figma 데스크톱 앱 + Claude Code CLI가 설치돼 있어야 합니다. 없으면 개발팀에 요청하세요. (Figma에서 "Figma Design Agent" 플러그인을 실행할 수 있는 권한도 필요)
  2. 저장소 폴더에서 Claude Code 실행 후, 이렇게 입력
    나디자인 생성 준비
    이 한마디로 AI가 환경 설치 → 브리지 확인 → 연결 검증 → 기획 문서 36건 학습·통독까지 자동으로 끝냅니다. 몇 분 걸리며, 중간에 아무것도 물어보지 않습니다.
  3. Figma 데스크톱 앱에서 플러그인 실행
    작업할 Figma 파일을 열고 → 플러그인 메뉴에서 "Figma Design Agent" 실행. 이것이 유일한 수동 단계입니다. 자동화가 불가능해서 사람이 눌러야 합니다.
  4. 준비 상태 확인 (선택)
    나doctor 실행해줘
    연결·설정 상태를 ✓/✗ 목록으로 점검해줍니다. 전부 ✓면 바로 그리기 시작.
⚠️
기획 문서 통독은 건너뛸 수 없습니다. AI가 src/기획/의 유스케이스 문서를 끝까지 읽고 확인 도장을 찍어야만 디자인 생성이 허용되도록 시스템이 강제합니다. 기획 문서가 수정되면 자동 감지되어 다시 읽게 됩니다 — "왜 또 읽지?"는 정상 동작입니다.

3화면 그리기 (일상 사용법)

준비가 끝난 상태라면, 그냥 말하면 됩니다. 지시가 구체적일수록 결과가 좋아지지만, 짧은 한마디도 통합니다 — AI가 기획 문서 맥락을 이미 알고 있기 때문입니다.

지시 예시

나메인화면 그려

나스테이지 상세 화면 그려줘. 와이어는 json/stage_detail_PRD.json 참고

나방금 만든 화면에서 히어로 영역이 너무 어두워. 뉴트럴하게 다시

나같은 화면으로 방향 다른 시안 3개 만들어줘

작업 흐름

  1. 지시하면 AI가 레퍼런스를 검색해 보고, 화면 설계도(blueprint)를 작성한 뒤 빌드합니다.
  2. 생성이 끝나면 AI가 스스로 스크린샷을 찍어 검증(QA)하고 결과를 보고합니다.
  3. Figma에서 결과를 확인하고, 고칠 점을 말로 피드백하거나 직접 수정합니다.
✅
직접 수정한 버전은 그대로 두세요 — 가장 강력한 학습 자료입니다. 같은 화면을 다시 만들 때 AI가 사용자 수정본을 먼저 학습하고 그 기준(타이포 크기, 여백, 색 사용)을 승계하도록 룰이 잡혀 있습니다.

알아둘 것

  • 같은 화면을 다시 그려도 매번 다르게 나옵니다. 의도된 설계입니다 — 콘텐츠(문구·숫자)는 와이어와 1:1로 유지하되, 시각 표현(구조·위계·컬러)은 매번 새로 설계하도록 시스템이 강제합니다.
  • 와이어에 없는 문구·배너를 AI가 지어내는 것은 금지돼 있습니다. 동적 콘텐츠 영역은 흰 placeholder로 나옵니다 — 오류가 아닙니다.
  • Status Bar·로고·하단 탭바 같은 공통 요소는 자동 처리됩니다. 지시에 포함할 필요 없습니다.

4알아두면 좋은 동작 원리

이 시스템의 핵심 설계는 "AI가 대충 만드는 것을 코드로 차단"하는 것입니다. 이 관점을 알면 이상해 보이는 동작들이 전부 설명됩니다.

빌드가 "차단"되는 건 고장이 아닙니다

생성 도중 게이트(gate)라는 자동 검문소들이 AI의 작업물을 검사합니다. 통과 못 하면 빌드가 멈추고, AI가 보완해서 다시 시도합니다. 담당자가 할 일은 없습니다 — 오히려 품질 장치가 일하고 있다는 신호입니다.

검문소차단하는 것
통독 게이트기획 문서를 읽지 않은 채 디자인 생성
콘텐츠 게이트와이어 문구·숫자의 누락 또는 날조
트레이싱 게이트와이어 배치를 그대로 베끼기 — 구조 재설계 없는 생성
신선도 게이트직전 결과물과 80% 이상 비슷한 재탕
검증 게이트레퍼런스를 안 보고 만들거나, 스크린샷 검증 없이 "완료" 선언

디자인 룰

수십 개의 디자인 룰이 등록돼 있고 AI가 매번 준수합니다. 예를 들어:

  • 버튼·탭바·인풋 등은 직접 그리지 않고 Imin Design System 컴포넌트를 씁니다
  • 색은 전부 DS 토큰 — 임의의 색상값 하드코딩 금지
  • 글자 크기는 DS 스케일(12/14/16/20/24/32…)만 사용
  • 브랜드 퍼플은 '나의 것'을 뜻하는 액센트로만, 완료 상태는 초록(success) 계열
  • 기본 톤은 뉴트럴(흰 카드 + 보더) — 다크 면을 기본값으로 쓰지 않음

전체 룰은 docs/design-rules-detail.md에 있지만 외울 필요 없습니다. AI가 관리하고, 바꾸고 싶으면 §6처럼 말로 시키면 됩니다.

DS 토큰은 자동으로 최신화됩니다

디자인 시스템 토큰(색·간격·텍스트 스타일)은 별도 레포 design-system에서 자동 동기화됩니다. 디자인 생성 직전에도 최신 여부를 확인하므로, DS가 업데이트되면 별도 조치 없이 다음 생성부터 반영됩니다.

5용어 사전

AI의 보고나 로그에 자주 등장하는 단어들입니다.

브리지 (bridge)
AI와 Figma 플러그인을 이어주는 백그라운드 프로그램. 데몬으로 등록돼 있어 컴퓨터 켜면 자동 실행됩니다.
플러그인
Figma 데스크톱 앱 안에서 실행하는 "Figma Design Agent". 실제로 화면을 그리는 손. 연결이 끊기면 재실행하면 됩니다.
blueprint (블루프린트)
AI가 작성하는 화면 설계도 JSON. 생성 성공 시 자동 삭제됩니다 — 재생성 때는 새로 씁니다(의도된 동작).
게이트 (gate)
품질 검문소. 통과 못 하면 빌드가 차단되고 AI가 보완 후 재시도합니다.
doctor
환경 종합 진단 명령. 연결·설정 상태를 ✓/✗로 보여주고 해결법을 안내합니다. 문제 발생 시 1순위.
통독 / ack
AI가 기획 문서를 끝까지 읽고(통독) 확인 도장(ack)을 찍는 절차. 이게 없으면 빌드가 차단됩니다.
DS 토큰
Imin Design System의 색·간격·radius 변수. 별도 레포에서 자동 동기화됩니다.
post-fix / QA
생성 직후 AI가 자동으로 실행하는 보정(정렬·사이징·토큰 바인딩)과 스크린샷 검증.

6룰을 바꾸고 싶을 때

룰 파일을 직접 편집할 필요 없습니다. AI에게 말로 시키면, 룰이 저장된 세 곳을 AI가 알아서 함께 갱신하고 커밋합니다.

나앞으로 리스트 화면 필터는 항상 DS Select 컴포넌트 써. 룰로 등록해줘

나카드에 그림자 기본으로 넣지 마. 룰 수정하고 커밋까지 해줘

이렇게 등록된 룰은 다음 세션부터 자동 적용됩니다. 생성 결과가 마음에 안 들 때 그때그때 피드백하는 것과 별개로, "앞으로 항상"이라고 말하면 룰로 남습니다.

💡
git 커밋·push도 AI에게 시키면 됩니다 ("커밋해줘"). 이 레포는 브랜치 없이 main에 직접 커밋하는 정책이며, AI가 알고 있습니다.

7문제가 생겼을 때

순서는 항상 같습니다: ① AI에게 "doctor 실행해줘" → ② 아래 표에서 증상 확인 → ③ 해결 안 되면 개발팀.

증상원인 · 해결
"플러그인 미연결"이라고 나옴Figma 데스크톱에서 "Figma Design Agent" 플러그인을 (다시) 실행하세요. 브리지가 재시작된 뒤에도 플러그인 재실행이 필요합니다.
빌드가 차단됐다고 나옴 (blocked)대부분 정상 — 게이트가 작동한 것이고 AI가 보완해 재시도합니다(§4). 통독 게이트면 AI가 기획 문서를 다시 읽습니다.
색·간격이 하나도 안 입혀진 회색 화면Figma 파일을 개인 Draft로 옮기면 팀 라이브러리 연결이 끊겨 이렇게 됩니다. 팀 프로젝트 안의 파일에서 작업하세요.
글자가 전부 기본 폰트로 나옴텍스트 스타일 연결 이슈 — AI에게 "텍스트 스타일 다시 적용해줘"라고 하면 복구 명령을 실행합니다.
생성이 5분 넘게 걸리다 실패타임아웃 — AI가 자동 복구 절차를 알고 있습니다. 그대로 AI에게 이어서 처리하라고 하세요.
예전 화면이 이상하게 변형돼 있음옛 빌드 잔재일 수 있습니다. AI에게 해당 화면 이름을 말하고 확인을 요청하세요.

개발팀에 넘겨야 하는 경우

  • doctor에서 브리지/빌드 관련 ✗가 해결 안 될 때 (Node·Python 설치 문제 등)
  • src/ 코드(브리지·플러그인) 수정이 필요한 기능 요청
  • 에러 원문에 406, patch, npm 같은 단어가 반복될 때

9새 규칙은 어디에 기록되는가 (기록 체계)

사용자가 규칙을 하나 가르치면(예: "이 버튼은 Secondary를 써야지"), AI는 그 규칙을 성격에 따라 최대 4곳에 나눠 기록합니다. 한 곳이 아니라 여러 층에 넣는 이유는, 각 층이 서로 다른 실패 경로를 막기 때문입니다.

층위치특징 / 언제 효력이 생기나
① 코드 (강제) scripts/convert_screen.py, scripts/verify_bindings.py, scripts/bind_semantic_tokens.py, src/figma-plugin/code.js 등 규칙의 실행형. 스크립트가 돌 때마다 자동 적용되거나(스왑·판정 로직), 게이트가 위반을 FAIL로 차단. 사람이 잊어도 기계가 강제 — 가장 강한 층. git 커밋으로 영구.
② 조회 가이드 ds/COMPONENT_GUIDANCE.json, CLAUDE.md, docs/design-rules-detail.md AI가 작업 전 조회하는 정본. component "Action Button"·rule 0-W 같은 명령으로 노출됨. CLAUDE.md는 매 세션 통째로 로드. 룰 개정 시 CLAUDE.md 인덱스 + 상세 원문 + 컴포넌트 가이드 세 곳 동기 갱신이 원칙.
③ 메모리 (교훈) ~/.claude/projects/…/memory/ 폴더의 개별 .md + MEMORY.md 인덱스 규칙의 "왜"와 실패 사례를 보존. 새 세션이 시작될 때 자동 로드되어 AI가 같은 실수를 반복하지 않게 함. 레포 밖(사용자 홈)에 있어 git과 무관하게 유지.
④ 감지기 (재발 감시) convert_screen.py의 diagnose() + verify_bindings.py 게이트 규칙 위반이 다시 발생하면 자동으로 flag/FAIL을 띄워 AI가 판단·수정하게 함(CONVERT-SUMMARY-JSON). "새 실패 클래스를 만나면 감지기 추가까지가 수정의 완료 조건"이 운영 원칙.
