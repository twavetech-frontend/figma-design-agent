1자동화 구조 정의서

디자인이 생성되기까지 데이터가 흐르는 전체 구조와, 각 구성요소의 역할·통신 방식입니다.

중요 — 실제 런타임 구조. 본 시스템은 별도의 데스크톱 앱(Electron)이 아니라 터미널 Claude Code CLI 기반으로 동작합니다. 설치된 패키지에 Electron·Vite는 없으며, 빌드 산출물(out/bridge/index.js)은 순수 Node 프로세스입니다.

1.1 전체 데이터 흐름 (5단계)

① 터미널 Claude Code CLI
사용자 요구사항(자연어·와이어프레임) 입력 + AI 오케스트레이션(요구사항 해석, 룰 적용 판단)을 수행하는 진입점.
▼ 요구사항 해석 → 빌드 명령
② Python 클라이언트 scripts/figma_mcp_client.py
빌드 파이프라인·룰 엔진. 검증 → 조립 → 빌드 → 후처리(post-fix) → 토큰 바인딩 → 자가검증. CLI가 Bash로 호출. (약 14,000줄)
▼ HTTP MCP (포트 8769)
③ Node 브리지 src/bridge/index.ts
중계 서버. WebSocket(8767, 플러그인 ↔) + HTTP MCP(8769, 클라이언트 ↔)를 동시 기동. Electron 의존성 없음. 70여 개 Figma 제어 도구 보유.
▼ WebSocket (포트 8767)
④ Figma 플러그인 "Figma Design Agent"
src/figma-plugin/code.js. Figma 데스크톱 앱 안에서 실행되며 브리지에 WebSocket으로 연결. 실제 노드 생성·수정 명령을 수행. (유일한 수동 단계: 플러그인 실행)
▼ Figma Plugin API
⑤ Figma 파일
디자인 시스템 변수·컴포넌트가 바인딩된 모바일 화면이 실제로 생성됨.

2프롬프트 설계 / 로직

본 시스템의 "프롬프트"는 한 줄의 명령문이 아니라, AI가 매번 일관된 품질과 디자인 시스템 준수를 보장하도록 만든 계층형 룰·게이트 엔진입니다.

설계 핵심. AI에게 자유롭게 "디자인해줘"라고 맡기면 결과 품질이 들쭉날쭉합니다. 그래서 ⓐ 따라야 할 규칙을 문서로 명문화하고(CLAUDE.md), ⓑ 그 규칙을 코드로 강제하는 룰 엔진을 두고(43개 룰), ⓒ 빌드 전후로 통과해야 하는 품질 게이트를 박았습니다.

2.1 규칙 명문화 — CLAUDE.md (프로젝트 룰북)

AI가 모든 작업에서 반드시 따르는 규칙 문서입니다. 핵심은 2계층 룰 체계입니다.

① 정합성 룰 (하드 — 항상 강제)

디자인이 깨지지 않도록 보장. 변경 불가.

  • 콘텐츠 1:1 (와이어 텍스트/숫자 그대로)
  • 디자인 시스템 컴포넌트·색 보존
  • 토큰/텍스트스타일/간격 변수 바인딩
  • 접근성(색 대비)·디바이스 규격(852px)
  • 레이아웃 무결성(요소 붕괴 방지)

② 스타일 룰 (기본값 — 작성자 선택이 우선)

획일화를 막기 위해 "명시 안 했을 때만 기본값" 으로 동작.

  • 카드 표면·보더·밴드 처리
  • 섹션 간격·여백
  • 타이포 위계·강조 색
  • → AI가 명시한 디자인 선택을 덮어쓰지 않음

2.2 품질·창의성 게이트 (빌드 차단 조건)

빌드 파이프라인은 다음 게이트를 통과해야만 진행됩니다. 통과 못 하면 빌드가 멈춰 품질 미달 결과물이 나오는 것을 원천 차단합니다.

게이트역할
기획 통독 게이트서비스 기획 문서(유스케이스)를 완독해야 빌드 허용 — 맥락 없는 생성 방지
레퍼런스 학습 (0-G)내장 레퍼런스 이미지(uibowl)를 실제로 열람·학습하도록 강제
콘텐츠 1:1 (0-E / S22·S23)와이어프레임의 텍스트·숫자를 그대로 반영했는지 검증
자가검증 (0-F)생성 결과 스크린샷을 AI가 재확인 — 체크리스트 12항목
컨셉 선언 (S24)이번 시안의 핵심 차별 아이디어를 명시해야 통과
디자인 방향 선언 (S25)이번 시안의 시각 방향(타이포·컬러·레이아웃·간격 전략) 선언
창의성 게이트 (novelty)직전 결과물과 너무 유사하면 차단 → 매 시안 다른 디자인 강제
창의성 보장 로직(핵심 설계). "콘텐츠는 동일하게(요구사항 충실), 비주얼은 매번 다르게"가 되도록, 결과물의 시각 시그니처(섹션 구성·색·간격·정렬·타이포 분포)를 저장해 직전 결과물과 비교합니다. 80% 이상 유사하면 빌드를 막아 레이아웃·컬러·간격·타이포를 다시 설계하게 합니다.

2.3 디자인 룰 엔진 — scripts/design_rules/ (43개 룰)

각 규칙은 4단계로 동작하는 코드 모듈입니다. 사람의 검수 없이도 일관된 디자인 결과를 보장합니다.

단계동작
Lint (검증)빌드 전 설계도(blueprint)에서 규칙 위반을 탐지·경고
Inject (자동 주입)빌드 직전 설계도를 자동 교정 (예: 탭을 올바른 컴포넌트로 변환)
Auto-fix (후처리)빌드된 실제 노드를 자동 수정 (예: 정렬·색 바인딩)
Verify (사후 검증)빌드 결과가 규칙을 지켰는지 최종 확인

예시 규칙: 상단 탭은 underline tabs로(R60), 하단 네비게이션은 DS 컴포넌트로(0-M), 상단 툴바는 DS Tool Bar 인스턴스로(0-W), 섹션 타이틀 좌측 정렬(R59) 등. 룰 번호 R05~R64, S20~S25.

3결과물 생성 코드 / 연동 방식

입력(요구사항·와이어프레임)을 받아 Figma에 실제 디자인을 생성하기까지의 코드 파이프라인과, 각 시스템 간 연동 방식입니다.

3.1 빌드 파이프라인 (결과물 생성 코드)

진입점은 scripts/figma_mcp_client.py(약 14,000줄)이며, 다음 순서로 동작합니다.

단계처리 내용
1. 조립 (assemble)고정 섹션(NavBar·TabBar 등)은 템플릿, 화면별 섹션만 작성해 설계도(blueprint) 생성
2. 검증·게이트§2의 룰 Lint + 콘텐츠/컨셉/방향/창의성 게이트 통과 확인
3. 레이아웃 시뮬레이션Yoga 엔진으로 빌드 전 레이아웃을 미리 계산해 오류 사전 차단
4. 빌드 (batch_build_screen)플러그인을 통해 Figma에 실제 노드 일괄 생성
5. 후처리 (post-fix)약 58개 자동 보정기 — 사이징·정렬·색/간격 변수 바인딩·텍스트 스타일 적용
6. 품질 검사 (QA)색 대비·레이아웃 무결성 자동 검사 + 자가검증(스크린샷 재확인)
7. 정리사용한 설계도·임시 산출물 자동 삭제

주요 CLI 명령 (연동 진입점)

# 디자인 빌드 (조립 → 빌드 → 자동 후처리)
python3 scripts/figma_mcp_client.py assemble scripts/my_config.json
python3 scripts/figma_mcp_client.py build    scripts/blueprint_xxx.json

# 개별 단계 / 운영 명령
python3 scripts/figma_mcp_client.py init            # 세션 초기화·연결 확인
python3 scripts/figma_mcp_client.py post-fix <id>   # 후처리 단독 실행
python3 scripts/figma_mcp_client.py learn-planning  # 기획 문서 학습
python3 scripts/figma_mcp_client.py sync-text-styles # DS 텍스트 스타일 동기화

3.3 디자인 시스템 연동 (Imin Design System)

디자인 결과물이 회사 디자인 시스템을 정확히 따르도록, 토큰·컴포넌트를 자동 동기화합니다.

산출물내용
ds/TOKEN_MAP.json · DESIGN_TOKENS.md색·간격·radius 등 디자인 토큰 (design-system 레포에서 자동 동기화)
ds/DS_COMPONENT_DOCS.json · COMPONENT_KEY_MAP.json버튼·뱃지·탭바 등 DS 컴포넌트 정의·키
ds/TEXT_STYLE_MAP.jsonDS 텍스트 스타일 매핑
references/uibowl/ · references/external/레퍼런스 화면 이미지 (toss·kakaopay 등 + 수집본) — 디자인 품질 학습용
요약. 결과물 생성은 ⓐ 코드(figma_mcp_client.py 빌드 파이프라인 + code.js 플러그인)와 ⓑ 연동(HTTP MCP ↔ WebSocket ↔ Figma API + DS 자동 동기화)의 결합으로 이뤄집니다.
