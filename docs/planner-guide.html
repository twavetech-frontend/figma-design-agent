Figma Design Agent
설치부터 화면 생성까지

터미널에 한국어로 “메인화면 그려”라고 말하면, imin 기획 문서와 디자인 시스템을 반영한 화면이 Figma 파일에 직접 그려집니다. 디자인 툴을 다룰 줄 몰라도 됩니다. 이 문서 하나로 설치와 일상 사용이 끝나도록 썼습니다.

figma-design-agent · 2026-09-21 기준
이 도구가 하는 일 준비물 설치와 첫 연결 매일 쓰는 법 어떻게 말할까 결과 읽는 법 기획 문서 관리 유의사항 문제 해결 용어 사전
1

이 도구가 하는 일

기획한 화면을 디자이너 일정에 기대지 않고, 말로 지시해 Figma에 실물 화면으로 만들어 봅니다.

설치 대상은 앱이 아니라 배관입니다. 실제로 일하는 주체는 터미널의 AI(Claude Code)이고, 나머지 부품들은 AI가 Figma 안에서 손을 움직일 수 있게 연결해 줍니다.

YOU기획자한국어로 지시
“이 PRD로 메인화면 그려”
AIClaude Code기획 문서 맥락 + 디자인 룰을 반영해 화면 설계
BRIDGE브리지AI와 Figma를 잇는 백그라운드 프로그램
FIGMA플러그인Figma 안에서 실제로 화면을 그리는 손
기획자가 직접 만지는 것은 둘뿐입니다. ① 터미널에 말로 지시하기, ② Figma에서 결과 보고 피드백하기. 가운데 과정(설계도 작성, 빌드, 검수)은 전부 AI가 알아서 합니다.

이런 작업에 씁니다

  • 기획 중인 화면을 눈으로 확인하고 싶을 때 — “스테이지 상세 화면 그려”
  • 손으로 그린 와이어프레임·캡처를 실제 UI 품질로 올리고 싶을 때
  • 같은 화면의 시안을 여러 개 비교하고 싶을 때 — “방향 다른 3안”
  • 리뷰·보고용으로 디자인 시스템에 맞는 화면이 급히 필요할 때
완성 디자인을 대체하진 않습니다. 만들어진 화면은 Imin Design System 컴포넌트·토큰으로 조립된 “진짜 Figma 파일”이라 디자이너가 그대로 이어받아 다듬을 수 있습니다. 기획–디자인 사이의 왕복을 줄이는 도구로 보시면 됩니다.
2

준비물 — 시작 전 확인

설치 스크립트가 알아서 해 주는 것과, 사람이 먼저 갖춰야 하는 것이 나뉩니다.

필요한 것왜 필요한가없을 때
Figma 데스크톱 앱플러그인은 데스크톱 앱 안에서만 실행됩니다. 브라우저 버전으로는 안 됩니다. figma.com/downloads 에서 설치
Claude Code지시를 해석하고 화면을 설계하는 AI 본체입니다. 설치·로그인은 사내 배포 방식을 따르세요. 직접 설치는 npm install -g @anthropic-ai/claude-code
Git이 저장소를 내려받는 데 씁니다. Mac은 설치 스크립트가 함께 처리. Windows는 git-scm.com
Figma 파일 권한화면을 그려 넣을 팀 프로젝트 파일에 편집 권한이 필요합니다. 팀에 편집자 권한 요청. 개인 Draft는 피하세요 — 디자인 시스템 연결이 끊깁니다.
터미널이 낯설어도 괜찮습니다. 처음에 명령어를 복사·붙여넣기 2번(저장소 내려받기 → Claude 실행) 하면 끝이고, 설치를 포함한 나머지는 평소 채팅하듯 한국어 문장으로 시킵니다.
· macOS: ⌘ + Space → “터미널” 검색   · Windows: 시작 메뉴 → “PowerShell”
3

설치와 첫 연결 — 처음 한 번만

사람이 직접 하는 일은 저장소 내려받기와 Figma 플러그인 실행 둘뿐입니다. 나머지 설치는 AI에게 “디자인 생성 준비”라고 말하면 알아서 합니다.

  1. 저장소 내려받기

    작업 폴더(예: 문서 폴더)를 정하고, 터미널에서 아래를 그대로 실행합니다.

    # 원하는 상위 폴더에서
git clone https://github.com/twavetech-frontend/figma-design-agent.git
cd figma-design-agent
  2. Claude Code 실행 
    claude

    Claude 데스크톱 앱을 쓰신다면, 앱에서 이 폴더를 열어 Code 탭에서 진행해도 똑같습니다.

  3. “디자인 생성 준비”라고 입력 — 설치까지 여기서 끝납니다
    나디자인 생성 준비

    이 한마디로 AI가 지금 쓰는 OS를 판단해 설치 스크립트를 직접 실행합니다. Python·Node 같은 실행 환경과 라이브러리 설치, 프로젝트 빌드, 브리지 기동, 연결 검증, 기획 문서 전체 학습까지 한 번에 진행됩니다. 이미 설치된 항목은 건너뛰므로 두 번째부터는 훨씬 빠릅니다.

    처음에는 5~15분 정도 걸리고, 중간에 아무것도 묻지 않습니다. 그동안 다른 일을 하셔도 됩니다.

    macOS 이럴 때만 손이 갑니다

    Homebrew 설치 단계에서 Mac 로그인 암호를 물을 수 있습니다. 입력해 주세요 (입력 중 화면에 글자가 안 보이는 게 정상입니다).

    Windows 이럴 때만 손이 갑니다

    winget이 없다는 안내가 나오면 Microsoft Store에서 “앱 설치 관리자”를 설치한 뒤 다시 “디자인 생성 준비”라고 하면 됩니다.

  4. Figma에 플러그인 등록하고 실행 — 유일한 수동 단계

    Figma 데스크톱 앱을 열고 (처음 한 번만) 상단 메뉴 Plugins → Development → Import plugin from manifest… → 내려받은 폴더의 src/figma-plugin/manifest.json 선택.

    이후에는 Plugins → Development → Figma Design Agent 로 실행만 하면 됩니다. 플러그인 창은 작업하는 동안 열어 둡니다(닫으면 연결이 끊깁니다).

  5. 상태 확인
    나doctor 실행해줘

    연결·설정 상태를 ✓ / ✗ 목록으로 점검해 줍니다. 전부 ✓면 바로 그리기 시작하면 됩니다. 문제가 있으면 무엇을 해야 하는지도 함께 알려줍니다.

“기획 문서를 또 읽는다”는 정상입니다. AI는 src/기획/ 폴더의 유스케이스 문서를 끝까지 읽어야만 화면 생성이 허용되도록 시스템이 막아 두었습니다. 기획 문서가 수정되면 자동으로 감지해 다시 읽습니다 — 덕분에 “메인화면 그려” 한마디에도 서비스 맥락이 반영됩니다.

참고 — 직접 실행해야 할 때의 명령

평소에는 쓸 일이 없습니다. 준비 도중 문제가 생겨 디자인팀이 요청할 때만 쓰세요.

설치 스크립트 직접 실행

# macOS
bash scripts/setup-mac.sh

# Windows
powershell -ExecutionPolicy Bypass -File scripts\setup-windows.ps1

브리지 상시 켜 두기

# macOS
npm run bridge:install

# Windows
npm run bridge:install:win

한 번 등록하면 컴퓨터를 켤 때마다 자동으로 뜹니다. 등록하지 않아도 AI가 필요할 때 띄워 줍니다.

4

매일 쓰는 법

설치가 끝난 다음 날부터는 이 네 줄이 전부입니다.

순서할 일걸리는 시간
1Figma 데스크톱에서 작업 파일 열고 플러그인 실행10초
2저장소 폴더에서 claude 실행 → “디자인 생성 준비”1~3분 (두 번째부터는 빠름)
3원하는 화면을 말로 요청화면당 3~5분
4Figma에서 결과 확인 → 고칠 점을 말로 피드백—
어디에 그려지나요? 지금 Figma에서 보고 있는 화면의 한가운데에 새 디자인이 생성됩니다. 특정 위치를 원하면 “선택한 와이어 오른쪽에 생성해줘”처럼 말해 주세요.
5

어떻게 말하면 되나

정해진 명령어는 없습니다. 후배 디자이너에게 구두로 요청하듯 말하면 됩니다.

① 기획 문서만으로 요청

AI가 이미 유스케이스를 학습한 상태라 짧은 한마디도 통합니다.

나메인화면 그려
나스테이지 참여 확인 바텀시트 만들어줘

② PRD·PSD 또는 와이어프레임 이미지 같이 주기

여기서 PSD는 Project Spec Document(제품 스펙 문서)의 줄임말입니다 — 포토샵 파일이 아닙니다.

문서나 이미지 파일은 경로를 알려주거나 터미널 창에 파일을 끌어다 놓으면 됩니다. Notion 문서는 링크를 그대로 붙여넣으면 됩니다.

나json/홈_거래현황_PRD.json 이 PRD로 홈 화면 그려줘
나이 캡처와 똑같은 구조로 만들어줘 (이미지 끌어다 놓기)
나https://www.notion.so/…/1인-다계정-PRD 이 문서 내용 분석해서 필요한 화면들 디자인 생성해

Notion 링크는 계정 연결(커넥터)이 돼 있어야 열립니다. 안 열린다고 하면 문서 내용을 복사해 붙여넣거나 PDF로 내려받아 주셔도 됩니다.

PRD·와이어 파일은 json/ 폴더에 두고 파일 이름에 PRD를 포함시키세요. 임시 산출물 자동 정리에서 제외되어 안전하게 남습니다.

③ Figma에 있는 와이어를 가리키며 요청

Figma에서 와이어프레임 프레임을 클릭해 선택한 상태로 이렇게 말하면 됩니다.

나선택한 와이어프레임을 디자인으로 만들어줘

④ 시안 비교 · 수정 요청

나같은 화면으로 방향 다른 시안 3개 만들어줘
나방금 만든 화면에서 히어로 영역이 너무 어두워. 밝고 뉴트럴하게 다시
나카드 안에 금액이 제일 먼저 보이게 위계 바꿔줘

⑤ “앞으로 항상” 은 담당 디자이너에게

같은 지적이 반복된다면 규칙으로 등록할 수 있습니다. 다만 규칙은 이 저장소를 관리하는 담당 디자이너가 등록·관리하는 영역이라, 기획자가 직접 등록하지는 않습니다. 아래처럼 원하는 내용을 정리해 담당 디자이너에게 전달해 주세요.

전달 예시리스트 화면 필터는 항상 DS Select 컴포넌트를 쓰도록 규칙에 넣어 주세요. 지금은 화면마다 필터 모양이 달라집니다.

등록된 규칙은 그다음 생성부터 모두에게 자동 적용됩니다. 매번 같은 지적을 반복하지 않아도 됩니다.

결과가 좋은 지시

  • 화면 이름 + 상태를 함께: “스테이지 상세 (참여 전) 화면”
  • 문구·숫자를 주기: 와이어의 실제 텍스트를 그대로 주면 지어내지 않습니다
  • 의도를 말하기: “첫 화면이라 가입 유도가 제일 잘 보여야 해”
  • 고칠 때 대상을 특정: “하단 CTA 위 안내 문구를 한 줄로”

아쉬운 지시

  • “예쁘게 만들어줘” — 판단 기준이 없어 결과가 매번 흔들립니다
  • “이거 고쳐줘” — 어느 화면·어느 영역인지 알 수 없습니다
  • 한 번에 5개 화면 요청 — 화면 단위로 나눠 요청하는 편이 빠르고 정확합니다
  • 색상 코드·픽셀 값 지정 — 디자인 시스템 값으로 자동 치환되니 의도를 말하는 편이 낫습니다
6

결과 읽는 법

처음 보면 “고장 났나?” 싶은 동작들이 있는데, 대부분 의도된 품질 장치입니다.

보게 되는 것의미
“빌드가 차단됐다(blocked)” 정상입니다. 자동 검문소가 부실한 결과물을 막은 것이고, AI가 보완해 다시 시도합니다. 기획자가 할 일은 없습니다.
같은 화면인데 매번 다르게 나옴 의도된 설계입니다. 문구·숫자는 와이어와 1:1로 지키되, 레이아웃·위계·색은 매번 새로 설계하도록 강제돼 있습니다. 마음에 든 버전은 그대로 두고 다음 요청을 하세요.
내용 없는 흰 박스(placeholder) 와이어에 내용이 없는 동적 영역입니다. 없는 문구를 지어내는 것이 금지돼 있어 빈 면으로 둡니다. 내용을 원하면 실제 문구를 주세요.
AI가 스크린샷을 찍어 스스로 점검 생성 직후 자동 QA입니다. 문제를 찾으면 고치고 다시 확인한 뒤 보고합니다.
Status Bar·탭바·로고가 자동으로 들어감 공통 요소는 자동 처리됩니다. 지시에 넣지 않아도 됩니다.
직접 수정한 버전은 지우지 마세요. 기획자·디자이너가 Figma에서 손본 화면은 AI에게 가장 강력한 학습 자료입니다. 같은 화면을 다시 만들 때 그 수정본의 글자 크기·여백·색 사용을 먼저 학습하고 따라갑니다.
7

기획 문서 관리 — 기획자만 할 수 있는 일

이 도구의 품질은 기획 문서의 품질을 그대로 따라갑니다. 여기가 기획자의 핵심 역할입니다.

무엇을어디에어떻게 반영되나
유스케이스 스펙 (정상/예외 플로우, 비즈니스 룰, 연결 화면) src/기획/ 폴더에 마크다운(.md) 권장 AI가 매번 통독합니다. 문서를 고치면 자동 감지해 다시 학습합니다.
화면 단위 PRD·와이어 데이터 json/ 폴더, 파일명에 PRD 포함 요청할 때 경로를 지목해 쓰고, 자동 정리에서 보호됩니다.
와이어 이미지·참고 캡처 아무 폴더나 (Figma 캔버스에 붙여넣어도 됨) 경로를 알려주거나 Figma에서 선택한 뒤 “이걸로 만들어줘”

문서를 고쳤을 때

따로 할 일이 없습니다. 다음 요청 때 AI가 변경을 감지해 다시 읽고 반영합니다. 바로 확인하고 싶으면 이렇게 말하면 됩니다.

나기획 문서 수정했어. 다시 학습해줘
정리는 자동입니다. 작업 중 생기는 임시 파일(설계도·스크린샷)은 7일이 지나면 자동 삭제됩니다. json/의 PRD 파일과 기획 문서는 삭제 대상이 아닙니다.

유의사항

기획 문서를 추가·수정할 때 자주 걸리는 두 가지입니다. 이것만 알면 "넣었는데 왜 반영이 안 되지?"를 피할 수 있습니다.

① 기획 문서는 마크다운(.md)이 가장 좋습니다

Notion에서 내보내기 → Markdown & CSV로 받아 src/기획/에 넣어 주세요. 다른 형식도 읽지만, 마크다운이 가장 정확하게 전달됩니다.

  • 제목·표·목록 구조가 그대로 전달됩니다 — 어느 값이 어느 항목인지 흐려지지 않습니다
  • 내용만 남습니다 — 지금 들어 있는 Notion HTML 문서는 파일 용량의 93%가 태그·스타일이고 실제 내용은 7%뿐입니다. 마크다운은 버릴 게 거의 없습니다
  • 무엇이 바뀌었는지 남습니다 — 문서를 고쳤을 때 변경된 줄을 확인할 수 있습니다
형식권장도메모
.md권장 Notion → Markdown & CSV로 내보내기. 구조가 가장 잘 보존됩니다.
.txt무난 내용은 온전하지만 제목·표 위계가 없어 긴 문서에선 불리합니다.
.html사용 가능 Notion 내보내기 HTML. 지금 들어 있는 유스케이스 문서가 이 방식입니다. 표가 평평해질 수 있습니다.
.docx사용 가능 Word 문서. 본문·표 텍스트를 읽고 이미지·도형·주석은 빠집니다.
.pdf되도록 피하기 한글이 깨져 나오는 PDF가 있고(폰트 정보 없는 경우), 표가 뒤섞입니다. 원본이 Notion·Word라면 그쪽 형식으로 넣어 주세요.

목록에 없는 형식(.pages, .key 등)은 그냥 지나칩니다. 와이어프레임·화면 캡처처럼 그림으로 봐야 하는 것은 PNG·JPG로 주시면 됩니다.

  • 읽지 못한 파일은 그냥 넘어가지 않고 학습 자료에 “읽기 실패”로 남고, PDF 글자가 깨지면 “추출 경고”가 표시됩니다 — AI가 보고해 주므로 조용히 누락되지 않습니다
  • 스캔한 PDF(사진처럼 찍힌 문서)는 글자가 없어 읽을 수 없습니다
  • 급할 때는 그 자리에서 Claude에게 파일을 주고 "이 문서 보고 ○○ 화면 그려"라고 해도 됩니다. 다만 그 세션 한정이고, 통독 대상(서비스 맥락)으로는 쌓이지 않습니다

② 새 세션을 열 필요는 없습니다

문서를 넣은 뒤 진행 중이던 대화에서 그대로 이렇게 말하면 됩니다.

나기획 문서 추가했어. 다시 학습해줘

폴더의 변경(파일 목록·수정시각·크기)을 감지해 학습 자료를 다시 만들고, 이전 통독 도장을 무효화한 뒤 다시 통독합니다. 분량에 따라 몇 분 걸립니다.

말하지 않고 그냥 화면 생성을 요청해도 됩니다. 빌드 게이트가 "통독 도장이 낡았다"는 것을 잡아내 차단하고, AI가 재학습·재통독을 거쳐 이어서 진행합니다. 새 세션을 여는 것과 결과는 같고, 오히려 진행 중이던 맥락을 잃지 않아 유리합니다.
9

문제가 생겼을 때

순서는 항상 같습니다. ① AI에게 “doctor 실행해줘” → ② 아래 표 확인 → ③ 그래도 안 되면 디자인팀.

증상원인과 해결
“플러그인이 연결되지 않았다” Figma 데스크톱 앱에서 “Figma Design Agent” 플러그인을 다시 실행하세요. 플러그인 창을 닫으면 연결이 끊깁니다.
아무 반응이 없다 / 화면이 안 그려진다 브리지가 꺼졌을 수 있습니다. AI에게 “브리지 다시 켜줘”라고 하거나 npm run bridge를 실행하세요.
색·간격이 하나도 안 입혀진 회색 화면 파일이 개인 Draft에 있으면 팀 디자인 시스템 연결이 끊깁니다. 팀 프로젝트 안의 파일에서 작업하세요.
글자가 전부 기본 폰트로 나온다 AI에게 “텍스트 스타일 다시 적용해줘”라고 하면 복구 명령을 실행합니다.
생성이 오래 걸리다 실패했다 타임아웃입니다. “이어서 복구해줘”라고 하면 AI가 남은 단계를 마저 처리합니다.
기존 화면이 이상하게 바뀐 것 같다 화면 이름을 알려주고 확인을 요청하세요. 되돌리려면 Figma의 ⌘Z 또는 버전 기록을 쓰면 됩니다.
한글이 깨져 보인다 Windows PowerShell을 새로 열고 다시 시도하세요. 계속되면 설치 스크립트를 한 번 더 실행하면 환경 설정이 복구됩니다.

디자인팀에 넘겨야 하는 경우

  • 설치 스크립트가 빨간 에러로 멈춤 (에러 화면을 그대로 복사해 전달)
  • doctor에서 브리지·빌드 관련 ✗가 반복적으로 해결되지 않음
  • 에러 메시지에 npm, 406, patch 같은 단어가 반복됨
가장 빠른 질문 창구는 사실 AI 자신입니다. 터미널에 “지금 왜 안 되는지 설명해줘”라고 물으면 이 저장소의 문서와 규칙을 읽고 원인을 짚어 줍니다.
10

용어 사전

AI의 보고나 로그에 자주 나오는 단어들입니다. 외울 필요는 없고, 눈에 익으면 충분합니다.

브리지 (bridge)
AI와 Figma 플러그인을 이어 주는 백그라운드 프로그램. 상시 등록해 두면 신경 쓸 일이 없습니다.
플러그인
Figma 데스크톱 앱 안에서 실행하는 “Figma Design Agent”. 실제로 화면을 그리는 손입니다.
blueprint
AI가 작성하는 화면 설계도. 생성에 성공하면 자동으로 지워집니다(정상 동작).
게이트 (gate)
품질 검문소. 통과하지 못하면 빌드를 막고 AI가 보완해 재시도합니다.
통독 / ack
AI가 기획 문서를 끝까지 읽고(통독) 확인 도장(ack)을 찍는 절차. 이게 없으면 화면 생성이 차단됩니다.
PRD · PSD
PRD는 화면 단위 요구사항 문서, PSD는 Project Spec Document(제품 스펙 문서)입니다. 포토샵 파일과 무관합니다.
DS · 토큰
Imin Design System의 컴포넌트와 색·간격·글자 스타일 변수. 자동으로 최신 상태를 따라갑니다.
doctor
환경 종합 진단. 문제가 생기면 가장 먼저 시키는 명령입니다.
QA
생성 직후 AI가 스스로 스크린샷을 찍어 규칙 위반을 점검하는 단계입니다.
